# Test Plan

Vitest + React Testing Library. 26 suites (527 tests). Four suites run against the real Docker Postgres; everything else mocks Prisma, `auth()`, OpenAI, TMDB, Wikipedia or `fetch`.

Run: `pnpm test` (about 21s, mostly the 7s and 11s lock tests). Skip the Postgres suites with `SKIP_PG_TESTS=1`; point them elsewhere with `PG_TEST_URL`. They only touch users they create and delete them afterwards.

## `vitest.setup.ts`

Sets dummy values for every required env var **before any test file is imported**, so `lib/env.ts` (which throws at module import if any var is missing) doesn't fail every suite. It also clears `OPENAI_MODEL` so every suite sees the default model, and installs a **network guard**: a wrapped global `fetch` that rejects any request to `api.openai.com`, `api.themoviedb.org` or `en.wikipedia.org`. A test that forgets to mock OpenAI or TMDB fails instead of calling the real service. Tests that stub `fetch` replace the guard for their duration; `vi.unstubAllGlobals()` restores it. `env.test.ts` is the one place that deliberately resets modules and re-imports with vars changed or removed, to prove the startup check works.

## How each suite is structured

- **Mocked Prisma** — `fact-service` uses a small in-memory fake of the calls the service makes, with an injected `Clock` (`{ now: () => t }`). `movie-service` and `api-routes` mock the Prisma client or the services directly.
- **Real Postgres** — `fact-lock`, `fact-authz`, `fact-route-authz` use `tests/helpers/pg.ts` (`PrismaClient` on port 5433, `connection_limit=20`). OpenAI is a `vi.fn` with a configurable sleep. `fact-route-authz` mocks `@/lib/prisma` to the test client and `@/lib/auth` to switch sessions.
- **Route handlers** — called directly with `Request` / `NextRequest`; `@/lib/auth` mocked per test.
- **Browser client** — `vi.stubGlobal('fetch', …)` returning real `Response` objects.
- **Components** — RTL `render` + `fireEvent`; `next/image` and `next/navigation` mocked; fake timers (`setTimeout`, `setInterval`, `Date`) for the debounce, the countdown and the auto-swap; `document.visibilityState` stubbed to test pausing. `fetch` returns plain response objects, routed by URL in `movie-edit.test.tsx`. The shared `factCache` and rate limiters are reset in `beforeEach`.

## CI (`.github/workflows/ci.yml`)

Runs on every push and pull request, on `ubuntu-latest` with a 15-minute timeout:

1. Postgres 16 service container (`movie` / `movie` / `movie_memory`, port 5432), health-checked with `pg_isready`.
2. pnpm (version from `packageManager`) + Node 22 with pnpm caching; `pnpm install --frozen-lockfile`.
3. `prisma generate`, then `prisma migrate deploy` against the service database (the same path as a fresh deploy).
4. `tsc --noEmit`, `eslint .`, `vitest run`. The three real-Postgres suites run against the service container via `PG_TEST_URL` (locally they default to the Docker port 5433).

Environment: dummy values only (`DATABASE_URL`, `PG_TEST_URL`, `AUTH_SECRET`, `GOOGLE_CLIENT_ID/SECRET`, `OPENAI_API_KEY`); `TMDB_API_KEY` unset; no `secrets.*`. OpenAI, TMDB and Wikipedia are mocked in every test and blocked by the network guard, so CI never calls them. Concurrent runs on the same branch are cancelled; the token is read-only.

## What is NOT tested (and why)

- **End-to-end (Playwright)** — out of scope; the layered service + route + component tests give high confidence without the flakiness tax.
- **OAuth round-trip** — mocking Google reliably is more work than it earns for a take-home; Auth.js owns that boundary.
- **Pino output content** — we test behavior, not log lines.
- **UI snapshot tests** — brittle and low signal for this component surface.
- **Real TMDB / OpenAI** — never called from tests.
